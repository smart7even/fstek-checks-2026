# 15.2. ЗКУ.2 Обеспечение целостности ПО конечного устройства

**Скрипт:** `fstek_audit/checks/ZKU/ZKU_02.sh`

Цель: Исключение несанкционированного изменения программного обеспечения конечного устройства.

Регламентирование: Не предъявляются.

Описание реализации, действий и результатов при испытаниях:

| Требование | Действие | Результат |
|------------|----------|-----------|
| В информационной системе должна обеспечиваться целостность операционных систем конечных устройств. | 1. На конечном устройстве (Astra Linux SE 1.7/1.8, ALT Linux или RED OS) проверить наличие контроля целостности: `systemctl is-active aide` / `aide --check` либо `rpm -Va` / `debsums` / `apt-get check` в зависимости от семейства ОС.<br><br>2. Изменить контрольный системный файл вне процедуры обновления и повторить проверку целостности. | 1. Успех: Механизм контроля целостности ОС установлен и выполняется.<br><br>2. Успех: Изменение зафиксировано. |
| Должна обеспечиваться целостность программного обеспечения средств защиты информации. | 1. Определить пакеты СЗИ (PARSEC, агент антивирусной защиты, auditd, межсетевой экран) и проверить их контрольные суммы пакетным менеджером.<br><br>2. Сопоставить результат с эталоном, заданным оператором. | 1. Успех: Целостность пакетов СЗИ подтверждена либо расхождение зафиксировано.<br><br>2. Успех: Эталон СЗИ задан; отклонения выявляются. |
| Должна обеспечиваться целостность иного программного обеспечения, определяемого в информационной системе. | Проверить по перечню оператора контрольные суммы назначенного прикладного ПО (`rpm -V`, `debsums`, AIDE-правила на каталоги приложения). | Успех: Целостность определенного оператором ПО контролируется. |
| На конечных устройствах должен быть обеспечен запрет на установку и запуск (инсталляцию) неразрешенного к использованию программного обеспечения. | 1. Проверить политики установки: права на `apt`/`apt-get`/`rpm`/`dnf`, наличие белого списка пакетов, `astra-update-lock` либо эквивалент.<br><br>2. Попытаться установить пакет, не входящий в разрешенный перечень, от имени непривилегированного пользователя и, при наличии политики, от имени администратора вне процедуры.<br><br>3. Попытаться запустить двоичный файл вне разрешенных путей. | 1. Успех: Установка ограничена политикой ОС.<br><br>2. Успех: Установка неразрешенного ПО отклонена.<br><br>3. Успех: Запуск неразрешенного ПО отклонен. |
| Обеспечение целостности программного обеспечения конечных устройств реализуется путем применения механизмов безопасности операционных систем и иных средств защиты информации. | Зафиксировать на устройстве задействованные механизмы: AIDE/FIM, проверка пакетов rpm/deb, блокировки установки Astra/ALT/RED, иные СЗИ контроля целостности. | Успех: Целостность обеспечивается механизмами безопасности ОС и (или) иными СЗИ. |
| Автопроверка Linux-хоста | `./check_all.sh --measure ЗКУ.2 --class K3` | Зафиксированы вердикты PASS/FAIL/SKIP/NA по локальным признакам (контроль целостности, возможность проверки пакетов). SKIP не считается провалом испытания СПО. |

Требования к усилению:

1) должна обеспечиваться доверенная загрузка операционных систем автоматизированных рабочих мест пользователей, на которых осуществляется обработка информации ограниченного доступа и (или) выполнение значимых функций оператора.
2) должна обеспечиваться доверенная загрузка операционных систем серверов, на которых осуществляется обработка информации ограниченного доступа и (или) выполнение значимых функций оператора.
3) должна обеспечиваться доверенная загрузка сетевых средств защиты информации.
4) должна обеспечиваться доверенная загрузка программного обеспечения телекоммуникационного оборудования.
5) должна обеспечиваться блокировка запуска программного обеспечения и (или) блокировка конечного устройства в случае обнаружения фактов нарушения целостности.
6) должен обеспечиваться контроль целостности базовой системы ввода-вывода конечных устройств.
7) должен обеспечиваться контроль целостности микропрограммного обеспечения и аппаратных компонентов конечных устройств.
8) должен обеспечиваться запрет применения функций разработки и отладки программ на конечных устройствах. При необходимости применения функций разработки и отладки программ должно обеспечиваться выполнение процедур контроля целостности программного обеспечения после завершения каждого процесса функционирования средств разработки и отладки программ.
