# fstek-checks-2026

Bash-комплект для технической проверки части мер защиты информации по методическому документу ФСТЭК России от 12.04.2026 на Linux-системах.

Структура проекта:

- отдельный скрипт на каждую меру: `check_<код>.sh`;
- общий запускатель: `check_all` и `check_all.sh`;
- режим усилений: `--with-enhancements` или `-e`;
- скрипты только читают состояние ОС и конфигурационные файлы.

## Поддерживаемые ОС

- Astra Linux Special Edition 1.7
- Astra Linux Special Edition 1.8
- ALT Linux
- RED OS

ОС определяется по `/etc/os-release` с учетом полей `ID`, `ID_LIKE`, `NAME`, `PRETTY_NAME` и `VERSION_ID`.

## Запуск

```bash
cd /path/to/fstek-checks-2026
sudo ./check_all
sudo ./check_all --with-enhancements
```

Одиночная проверка:

```bash
sudo ./check_zks1.sh
sudo ./check_zks1.sh --with-enhancements
```

## Вывод

Используются статусы:

- `PASS` - параметр технически подтвержден;
- `FAIL` - параметр технически проверяем, но не подтвержден;
- `SKIP` с пометкой `НЕПРИМЕНИМО` - компонент/технология на узле не обнаружены;
- `SKIP` с пометкой `НЕВОЗМОЖНО ПРОВЕРИТЬ АВТОМАТИЧЕСКИ` - параметр требует документации, исходного кода, MDM/IdP/СЗИ-консоли, сетевой схемы или организационной проверки.

В интерактивном терминале статусы подсвечиваются цветом: `PASS` зеленым, `FAIL` красным, `SKIP` желтым. Цвет можно отключить через `NO_COLOR=1` или `FSTEK_COLOR=never`, а принудительно включить через `FSTEK_COLOR=always`.

Итог `check_all` выводит:

- общий результат `ОК`/`НЕ ОК`;
- число выполненных технических проверок;
- число успешных и неуспешных проверок;
- процент невыполненных проверок;
- меры и параметры с `FAIL`;
- параметры, которые невозможно проверить автоматически или неприменимы.

## Ограничения

Скрипты проверяют только то, что можно получить с самого Linux-узла штатными средствами: файлы конфигурации, службы, журналы, PAM, firewall, audit, SSH, сетевые параметры, признаки WAF/IDS/AV/SIEM/MDM/IoT/Wi-Fi.

Параметры, зависящие от утвержденных документов, сетевой архитектуры, внешних СЗИ, облачных сервисов, исходного кода приложения, IdP, MDM-консоли или фактических процедур персонала, намеренно помечаются как неавтоматизируемые.

## Важно

Проект не изменяет настройки системы. Скрипты предназначены для первичной технической инвентаризации и не заменяют экспертную оценку, анализ документации и проверку фактической реализации организационных мер.
