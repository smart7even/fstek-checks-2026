# 14.2. ЗПИ.2 Управление доступом пользователей и приложений API

**Скрипт:** `fstek_audit/checks/ZPI/ZPI_02.sh`

Цель: Исключение несанкционированного доступа к СПО субъектов доступа (пользователей и приложений), взаимодействующих с программным обеспечением СПО посредством API, не прошедших процедуру аутентификации.

Регламентирование: Не предъявляются.

Описание реализации, действий и результатов при испытаниях:

| Требование | Действие | Результат |
|------------|----------|-----------|
| В СПО должно быть осуществлено определение перечня API, для которых требуется контроль доступа пользователей и приложений. | Сопоставить перечень API из эксплуатационной документации с фактически доступными методами https://example.ru/api и выделить методы, для которых требуется контроль доступа. | Успех: Перечень определен; методы с контролем доступа отличаются от общедоступных ресурсов. |
| Должны быть обеспечены идентификация и аутентификация пользователей, взаимодействующих с программным обеспечением СПО посредством API, в соответствии с мерами защиты информации ИАФ.1, ИАФ.3. | 1. Вызвать защищенный метод https://example.ru/api с действительным аутентификатором непривилегированного пользователя.<br><br>2. Вызвать тот же метод с действительным аутентификатором привилегированного пользователя.<br><br>3. Вызвать метод без аутентификатора и с недействительным аутентификатором. | 1. Успех: Запрос принят; пользователь идентифицирован и аутентифицирован.<br><br>2. Успех: Запрос принят; привилегированный пользователь идентифицирован и аутентифицирован.<br><br>3. Успех: Запрос отклонен (401). |
| Должно быть обеспечено управление доступом пользователей и приложений, получающих доступ к СПО посредством входящих в перечень API, в соответствии с мерами защиты информации УПД.1 – УПД.6. | 1. Вызвать метод https://example.ru/api, не разрешенный роли пользователя.<br><br>2. Вызвать метод от имени приложения (client_id), для которого метод не разрешен.<br><br>3. Вызвать разрешенный метод от имени того же пользователя и того же приложения. | 1. Успех: Запрос отклонен (403).<br><br>2. Успех: Запрос отклонен (403).<br><br>3. Успех: Запрос выполнен в пределах назначенных прав. |
| Должно быть обеспечено ограничение числа параллельных сеансов доступа к API в соответствии с мерой защиты информации УПД.7. | Открыть для одной учетной записи (одного приложения) число параллельных сеансов доступа к https://example.ru/api, превышающее установленное оператором ограничение. | Успех: Сеансы сверх ограничения не созданы либо ранее открытый сеанс завершен. |
| Должно быть обеспечено автоматическое завершение сеансов доступа к API при неактивности в соответствии с мерой защиты информации УПД.8. | Получить сеанс доступа к https://example.ru/api, выдержать установленное оператором время неактивности и повторить вызов защищенного метода тем же аутентификатором сеанса. | Успех: Сеанс автоматически завершен; повторный вызов требует новой аутентификации. |
| Должна выполняться проверка прав доступа субъектов доступа при каждом обращении (запросе) к API, за исключением определенных общедоступных ресурсов, в соответствии с мерой защиты информации УПД.9. | 1. Вызвать защищенный метод https://example.ru/api после отзыва права у действующего сеанса.<br><br>2. Вызвать общедоступный ресурс API, указанный в ОРД как доступный до идентификации.<br><br>3. Повторить вызов защищенного метода без сеанса. | 1. Успех: После отзыва права запрос отклонен; проверка выполняется на каждый запрос.<br><br>2. Успех: Общедоступный ресурс доступен в пределах УПД.9.<br><br>3. Успех: Запрос отклонен (401). |
| Должны быть установлены ограничения на частоту и объем обращений к программным интерфейсам (API), а также порядок автоматического выявления и пресечения попыток подбора средств аутентификации. | 1. Превысить установленные оператором частоту и объем обращений к https://example.ru/api от одного клиента.<br><br>2. Направить последовательность запросов аутентификации к API с перебором средств аутентификации. | 1. Успех: Последующие обращения отклонены (ограничение частоты/объема).<br><br>2. Успех: Подбор выявлен автоматически и пресечен. |
| Автопроверка Linux-хоста | `./check_all.sh --measure ЗПИ.2 --class K3` | Зафиксированы вердикты PASS/FAIL/SKIP/NA по локальным признакам (аутентификация/ACL API, ограничение частоты). SKIP не считается провалом испытания СПО. |
