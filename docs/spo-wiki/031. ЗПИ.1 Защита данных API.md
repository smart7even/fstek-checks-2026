**Цель**: Исключение несанкционированного доступа к СПО при использовании программных интерфейсов взаимодействия приложений (API).

**Регламентирование**: В эксплуатационной документации для СПО должны быть определены:

- перечни API, предоставляемых внешним и внутренним пользователям СПО;
- требования к режимам и настройкам, обеспечивающим конфиденциальность данных API.

Описание реализации, действий и результатов при испытаниях:

| Требование | Действие | Результат |
|------------|----------|-----------|
| Минимизируется объем информации, раскрывающей структуру СПО, в ответах API и в сообщениях об ошибках. | Вызвать https://example.ru/api документированным методом, несуществующим методом и запросом с прикладной ошибкой. | Успех: Ответы не содержат трассировки, путей, имен узлов и служебных сведений сверх необходимого. |
| Аутентификаторы доступа к API не содержат сведений о структуре СПО. Внешний доступ к API защищен по каналу. | Получить токен API и просмотреть его открытую часть; вызвать API по HTTP и с недействительным сертификатом. | Успех: Токен не раскрывает структуру СПО; незащищенное соединение отклонено. |
| **Условия: К2, К1.** Усиление 1: ежегодный пересмотр режимов и настроек ПО, реализующего API. | Открыть на example.ru/admin дату последнего пересмотра настроек API и результаты выявления уязвимостей конфигурации. | Успех: Пересмотр проведен в пределах года; результаты зафиксированы. |

**Параметры безопасности в интерфейсе администратора безопасности (СПБ.5):**

Все перечисленные параметры должны быть доступны для оперативного редактирования из интерфейса СПО (`example.ru/admin`) администратору безопасности, с ограничениями, исключающими ослабление политик безопасности ниже значений, установленных методикой и требованиями к СПО (мера СПБ.5).

- перечень внешних и внутренних API;
- режим подробности сообщений об ошибках;
- срок жизни и состав аутентификаторов API;
- дата последнего пересмотра настроек API.
