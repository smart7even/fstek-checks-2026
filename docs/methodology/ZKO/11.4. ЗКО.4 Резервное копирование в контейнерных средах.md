# 11.4. ЗКО.4 Резервное копирование в контейнерных средах

**Скрипт:** `fstek_audit/checks/ZKO/ZKO_04.sh`

Цель: Обеспечение возможности восстановления функционирования контейнерной среды информационной системы.

Регламентирование: В эксплуатационной документации на информационную систему должен быть определен порядок резервного копирования контейнерной среды.

Описание реализации, действий и результатов при испытаниях:

| Требование | Действие | Результат |
|------------|----------|-----------|
| При применении контейнерной среды должно обеспечиваться резервное копирование образов контейнеров. Мера реализуется за счет применения средств резервного копирования. | 1. Выгрузить образы: `docker save -o /backup/zko4-app.tar <образ>`, `podman save`, `crictl inspecti` + сохранение digest из внутреннего реестра; для Kubernetes — `velero backup create zko4-img --include-namespaces <ns>` либо снимок реестра Harbor/Nexus.<br><br>2. Удалить локальный образ: `docker rmi`, `podman rmi`, `crictl rmi`; удалить Deployment.<br><br>3. Восстановить: `docker load -i /backup/zko4-app.tar`, `podman load`, повторный `crictl pull` по сохранённому digest, `velero restore create --from-backup zko4-img`; запустить контейнер (`docker run`, `kubectl apply`). | 1. Успех: Резервная копия образов создана и доступна на носителе копирования.<br><br>2. Успех: Рабочие образы удалены из среды исполнения.<br><br>3. Успех: Образы восстановлены с тем же digest; контейнер/под запускается и функционирует. |
| Автопроверка Linux-хоста | `./check_all.sh --measure ЗКО.4 --class K3` | Зафиксированы вердикты PASS/FAIL/SKIP/NA по локальным признакам (свежие копии образов в каталогах backup, Velero Completed, задания копирования). SKIP не считается провалом испытания СПО. |

Требования к усилению:

1) должно обеспечиваться резервное копирование параметров настройки средств контейнеризации;
2) должно обеспечиваться резервное копирование сведений о событиях безопасности в среде контейнеризации.
