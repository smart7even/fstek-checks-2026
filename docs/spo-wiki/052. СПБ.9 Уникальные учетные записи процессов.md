**Цель**: Для аутентификации процессов СПО используются уникальные специальные учетные записи с минимально необходимыми привилегиями.

**Регламентирование**: Не предъявляются.

Описание реализации, действий и результатов при испытаниях:

| Требование | Действие | Результат |
|------------|----------|-----------|
| **Субъект: Процессы и приложения СПО.**<br><br>У каждого процесса своя технологическая учетная запись. | Открыть на example.ru/admin перечень технологических УЗ процессов и сверить с фактически запущенными процессами/интеграциями. | Успех: Общих и пользовательских УЗ у процессов нет; у каждого процесса своя УЗ. |
| Процессу нельзя назначить привилегии администратора безопасности сверх минимума. | Попытаться назначить процессу роль администратора безопасности или право менять политики. | Успех: Избыточные привилегии отклонены. |
| Чужая УЗ не принимается для вызова API процесса. | Вызвать API процесса с УЗ другого процесса и с пользовательской УЗ. | Успех: Вызов отклонен. |

**Параметры безопасности в интерфейсе администратора безопасности (СПБ.5):**

Все перечисленные параметры должны быть доступны для оперативного редактирования из интерфейса СПО (`example.ru/admin`) администратору безопасности, с ограничениями, исключающими ослабление политик безопасности ниже значений, установленных методикой и требованиями к СПО (мера СПБ.5).

- перечень технологических учетных записей процессов;
- минимальные права каждой технологической УЗ.
