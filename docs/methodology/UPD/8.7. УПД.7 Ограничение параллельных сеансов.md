# 8.7. УПД.7 Ограничение параллельных сеансов

**Скрипт:** `fstek_audit/checks/UPD/UPD_07.sh`

Цель: Ограничение числа параллельных сеансов доступа от имени учетной записи к СПО.

Регламентирование: В эксплуатационной документации для СПО должны быть определены:

- значения максимально допустимого числа параллельных сеансов доступа для различных типов учетных записей;
- порядок учета и регистрации активных сеансов доступа для каждой учетной записи;
- порядок автоматического учета активных сеансов и реализации заданных ограничений;
- порядок уведомления пользователя при превышении числа параллельных сеансов;
- порядок оповещения администраторов о превышении лимитов активных сеансов учетных записей;
- объем сведений в оповещающем сообщении, например, дата, время, место и устройство предыдущих входов, предложение завершить активные сессии.

Описание реализации, действий и результатов при испытаниях:

| Требование | Действие | Результат |
|------------|----------|-----------|
| В СПО должны обеспечиваться возможность задавать ограничения на число параллельных сеансов доступа, основываясь на идентификаторах учетных записей. Число параллельных сеансов может быть задано для информационной системы в целом, для отдельных сегментов, для групп пользователей, отдельных пользователей или их комбинаций. | Войти в СПО на example.ru/admin с правами администратора безопасности и задать предельное число параллельных сеансов для непривилегированной УЗ, для группы и для привилегированной УЗ. | Успех: Ограничения заданы на основе идентификаторов учетных записей (и при необходимости для групп, сегментов или системы в целом) и доступны для изменения. |
| В СПО должны обеспечиваться автоматический учет активных сеансов доступа для каждой учетной записи пользователей, устройств и приложений и автоматическое ограничение числа параллельных сеансов доступа для каждой такой учетной записи. | 1. | В случае попытки входа от имени учетных записей непривилегированных или привилегированных пользователей, для которых достигнуто максимальное значение допустимых параллельных сеансов, при успешной аутентификации должно выдаваться сообщение о превышении числа параллельных сеансов доступа, месте (местах) их предыдущего входа с активными сессиями и предложением отключения этой сессии (этих сессий). | 1. Успех: Аналогичное сообщение выдано привилегированному пользователю.<br><br>3. Успех: Указанная сессия отключена; новый сеанс открыт в пределах лимита. |

SKIP не считается провалом испытания СПО. |

Требования к усилению:

1) в информационной системе для учетных записей привилегированных пользователей (администраторов, администраторов безопасности) количество параллельных (одновременных) сеансов (сессий) не должно превышать следующих значений:
а) не более 2;
б) не более 1.
