# 11.6. ЗКО.6 Идентификация, аутентификация и защита сетевого взаимодействия

**Скрипт:** `fstek_audit/checks/ZKO/ZKO_06.sh`

Цель: Исключение несанкционированного доступа субъектов доступа, не прошедших идентификацию и аутентификацию, к объектам доступа в контейнерной среде.

Регламентирование: В эксплуатационной документации на информационную систему должен быть определен порядок идентификации и аутентификации субъектов доступа в контейнерной среде.

Описание реализации, действий и результатов при испытаниях:

| Требование | Действие | Результат |
|------------|----------|-----------|
| Субъект: Разработчик образов контейнеров.<br><br>Должна обеспечиваться в соответствии с ИАФ.1, ИАФ.3 идентификация и аутентификация пользователей, реализующих роль разработчика образов контейнеров. | 1. Предъявить идентификатор и пройти аутентификацию: `docker login <реестр>`, `podman login`, push образа (`docker push`, `podman push`).<br><br>2. Повторить `docker push` / `crictl pull` без учётных данных и с неверным паролем.<br><br>3. Проверить, что разработчик не выполняет операции администратора средства контейнеризации (`kubectl get nodes`, `systemctl restart crio`). | 1. Успех: Разработчик идентифицирован и аутентифицирован; push в разрешенный репозиторий выполнен.<br><br>2. Успех: Доступ без успешной аутентификации отклонён.<br><br>3. Успех: Операции вне роли разработчика недоступны. |
| Субъект: Администратор безопасности средств контейнеризации.<br><br>Должна обеспечиваться идентификация и аутентификация администратора безопасности средств контейнеризации. | 1. Войти с учётной записью администратора безопасности (kubeconfig/Role `security-admin`, группа хоста).<br><br>2. Выполнить просмотр политик: `kubectl get validatingwebhookconfigurations`, `kubectl auth can-i get pods --all-namespaces`, чтение журналов Falco/audit.<br><br>3. Войти без второго фактора/с истекшим паролем (по ИАФ.3) и без идентификатора. | 1. Успех: Администратор безопасности идентифицирован и аутентифицирован.<br><br>2. Успех: Доступны функции контроля, изменение рабочих нагрузок вне роли запрещено.<br><br>3. Успех: Доступ без идентификации и аутентификации исключён. |
| Субъект: Администратор средств контейнеризации.<br><br>Должна обеспечиваться идентификация и аутентификация администратора средств контейнеризации. | 1. Войти как администратор Docker/Podman/CRI-O/Kubernetes (`kubectl` с ClusterRole admin, член группы `docker`).<br><br>2. Выполнить `docker ps`, `crictl pods`, `kubectl get deploy -A`, `systemctl status crio`.<br><br>3. Обратиться к API без TLS/токена: `curl --unix-socket /var/run/docker.sock http://localhost/containers/json` от имени постороннего пользователя. | 1. Успех: Администратор средств контейнеризации идентифицирован и аутентифицирован.<br><br>2. Успех: Операции управления контейнерами доступны в пределах роли.<br><br>3. Успех: Неаутентифицированный доступ к API отклонён. |
| Субъект: Администратор хостовой операционной системы.<br><br>Должна обеспечиваться идентификация и аутентификация администратора хостовой операционной системы. Мера реализуется за счет встроенных механизмов средства контейнеризации и хостовой ОС. | 1. Войти на хост по SSH/консоли с учётной записью администратора хостовой ОС (ИАФ.1, ИАФ.3).<br><br>2. Выполнить администрирование ОС (`systemctl`, правка `/etc/docker/daemon.json`) и убедиться, что вход без идентификации невозможен.<br><br>3. Повторить вход с неверным паролем и проверить блокировку по ИАФ.3. | 1. Успех: Администратор хостовой ОС идентифицирован и аутентифицирован.<br><br>2. Успех: Доступ к хосту без идентификации и аутентификации исключён.<br><br>3. Успех: Неуспешные попытки обрабатываются по ИАФ.3. |
| Автопроверка Linux-хоста | `./check_all.sh --measure ЗКО.6 --class K3` | Зафиксированы вердикты PASS/FAIL/SKIP/NA по локальным признакам (RBAC/группы ролей, TLS реестров, защита API docker/podman). SKIP не считается провалом испытания СПО. |

образы контейнеров;
контейнеры;
средства контейнеризации.
