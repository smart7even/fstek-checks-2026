# 17.3. ЗИВ.3 Защита данных IoT

**Скрипт:** `fstek_audit/checks/ZIV/ZIV_03.sh`

Цель: Предотвращение утечек, несанкционированного изменения или ограничения доступа к данным устройств «интернета вещей».

Регламентирование: Не предъявляются.

Описание реализации, действий и результатов при испытаниях:

| Требование | Действие | Результат |
|------------|----------|-----------|
| При реализации мер по защите данных устройств «интернета вещей» должна обеспечиваться инвентаризация устройств «интернета вещей» с целью выявления неиспользуемых устройств, а также устройств, не предусмотренных к использованию. | 1. На шлюзе IoT выгрузить перечень поставленных на учет устройств и сравнить с фактическими сессиями брокера.<br><br>2. Подключить к сегменту устройство, не предусмотренное к использованию, либо оставить зарегистрированное устройство без функции. | 1. Успех: Инвентаризационный перечень сформирован на шлюзе.<br><br>2. Успех: Непредусмотренное или неиспользуемое устройство выявлено. |
| Должна обеспечиваться возможность подключения только к разрешенным устройствам «интернета вещей» для выполнения установленных функций. | 1. На шлюзе/брокере разрешить сессии только для устройств из перечня onboarding.<br><br>2. Установить MQTT-сессию с разрешенного устройства.<br><br>3. Установить MQTT-сессию с устройства вне перечня. | 1. Успех: Политика подключения только к разрешенным устройствам включена.<br><br>2. Успех: Сессия установлена.<br><br>3. Успех: Сессия отклонена. |
| Должно обеспечиваться ограничение формата данных (команд), вводимых в устройства «интернета вещей». | 1. На шлюзе задать допустимый формат сообщений/команд (схема payload MQTT).<br><br>2. Опубликовать в топик исполнительного устройства команду допустимого формата.<br><br>3. Опубликовать команду недопустимого формата. | 1. Успех: Ограничение формата задано на шлюзе.<br><br>2. Успех: Команда принята устройством/шлюзом.<br><br>3. Успех: Команда отклонена фильтром сообщений. |
| Должно обеспечиваться отключение в устройствах «интернета вещей» неиспользуемых средств (протоколов) подключения (коммуникации) между устройствами «интернета вещей» в вычислительной сети устройств «интернета вещей»; отключение неиспользуемых функциональных возможностей устройств «интернета вещей». | 1. На шлюзе и устройстве отключить неиспользуемые протоколы и функции (открытый MQTT без TLS, Telnet, незаявленные порты).<br><br>2. Попытаться установить соединение по отключенному протоколу. | 1. Успех: Неиспользуемые протоколы и функции отключены.<br><br>2. Успех: Соединение не устанавливается. |
| Должно обеспечиваться выделение сетей устройств «интернета вещей» в отдельные сегменты информационной системы. | 1. На шлюзе и межсетевом экране проверить, что сеть устройств «интернета вещей» выделена в отдельный сегмент.<br><br>2. С хоста вне сегмента IoT обратиться к брокеру по управлению устройствами. | 1. Успех: Сегмент IoT отделен от прочих сегментов.<br><br>2. Успех: Обращение из чужого сегмента отклонено. |
| Должна обеспечиваться защита данных устройств «интернета вещей» от раскрытия, модификации и навязывания (ввода ложной информации) при их передаче по каналам связи, имеющим выход за пределы контролируемой зоны. | 1. На брокере включить MQTT over TLS (или эквивалентный защищенный канал) для обмена за пределами контролируемой зоны.<br><br>2. С перехватывающего узла зафиксировать payload сессии без ключей TLS.<br><br>3. Попытаться навязать устройству ложную команду вне защищенного канала. | 1. Успех: Защищенный канал обязателен для внешнего обмена.<br><br>2. Успех: Payload недоступен в открытом виде.<br><br>3. Успех: Навязанная команда отклонена. |
| Субъект: Устройства «интернета вещей».<br><br>Условия: У Системы К2, К1.<br><br>Должно обеспечиваться исключение возможности ввода данных (команд) в устройства «интернета вещей» посредством реализации ограничительных интерфейсов по вводу информации. | 1. На шлюзе/устройстве оставить только ограничительный интерфейс ввода команд (управляющий топик с ACL, без открытого API ввода).<br><br>2. Попытаться ввести команду через отключенный или незаявленный интерфейс. | 1. Успех: Ввод команд возможен только через ограничительный интерфейс.<br><br>2. Успех: Ввод через незаявленный интерфейс невозможен. |
| Автопроверка Linux-хоста | `./check_all.sh --measure ЗИВ.3 --class K3`<br><br>`./check_all.sh --measure ЗИВ.3 --class K2 --with-enhancements` | Зафиксированы вердикты PASS/FAIL/SKIP/NA по локальным признакам (наличие IoT-шлюза/брокера, TLS). SKIP не считается провалом испытания СПО. |

Требования к усилению:

1) должно обеспечиваться исключение возможности ввода данных (команд) в устройства «интернета вещей» посредством реализации ограничительных интерфейсов по вводу информации;

2) должен обеспечиваться анализ сетевого трафика сетей устройств «интернета вещей» с целью выявления признаков реализации компьютерных атак.
