# 18.1. ЗБД.1 Идентификация и аутентификация точек беспроводного доступа

**Скрипт:** `fstek_audit/checks/ZBD/ZBD_01.sh`

Цель: Исключение доступа объектов и субъектов беспроводного доступа к информационной системе, не прошедших процедуру идентификации и аутентификации.

Регламентирование: Не предъявляются.

Описание реализации, действий и результатов при испытаниях:

| Требование | Действие | Результат |
|------------|----------|-----------|
| Субъект: Внутренние непривилегированные пользователи, привилегированные пользователи, администраторы.<br><br>Должны обеспечиваться идентификация и аутентификация пользователей, запрашивающих доступ к беспроводной локальной вычислительной сети, в соответствии с мерами защиты информации ИАФ.1, ИАФ.3. | 1. На контроллере беспроводной сети (или в `/etc/hostapd/hostapd.conf`) убедиться, что SSID корпоративной сети использует WPA2-Enterprise/WPA3-Enterprise: `wpa=2`, `ieee8021x=1`, `wpa_key_mgmt=WPA-EAP`, указан RADIUS (`auth_server_addr`).<br><br>2. Подключить АРМ непривилегированного пользователя к SSID через `wpa_supplicant` (EAP-TLS или PEAP) с ранее зарегистрированными учетными данными.<br><br>3. Подключить АРМ привилегированного пользователя и администратора тем же способом. | 1. Успех: Точка доступа/контроллер требует 802.1X; открытая сеть и WPA-PSK с паролем по умолчанию не применяются.<br><br>2. Успех: Ассоциация и авторизация выполнены только после успешной идентификации и аутентификации.<br><br>3. Успех: Привилегированный пользователь и администратор допущены с их учетными данными. |
| Субъект: Устройства пользователей.<br><br>Должна обеспечиваться идентификация устройств, запрашивающих доступ к беспроводной локальной вычислительной сети, в соответствии с мерой защиты информации ИАФ.2. Идентификация устройств при подключении обеспечивается по логическим именам (имя устройства и (или) ID), логическим адресам (IP) и (или) по физическим адресам (MAC) либо по их комбинации. | 1. На контроллере/RADIUS зафиксировать идентификатор устройства (MAC, имя, сертификат EAP-TLS).<br><br>2. Подключить зарегистрированное устройство к SSID.<br><br>3. Подключить незарегистрированное устройство (иной MAC/сертификат). | 1. Успех: Идентификатор устройства однозначно сопоставлен с записью в контроллере/RADIUS.<br><br>2. Успех: Доступ предоставлен идентифицированному устройству.<br><br>3. Успех: Доступ отклонен. |
| Должна обеспечиваться идентификация точек беспроводного доступа по логическим именам (SSID), логическим адресам (IP) и (или) по физическим адресам (MAC) либо по комбинации имени, логического и (или) физического адресов. | 1. Снять идентификаторы AP с контроллера или `hostapd_cli status` / `iw dev wlan0 info`: SSID, BSSID (MAC), IP управления.<br><br>2. Сопоставить значения с инвентарным перечнем точек доступа. | 1. Успех: Для каждой штатной AP получены SSID, MAC и (или) IP.<br><br>2. Успех: Идентификаторы однозначно соответствуют инвентарю, дубликатов нет. |
| Не допускается осуществлять аутентификацию точек беспроводного доступа с использованием паролей, установленных по умолчанию. | 1. По документации производителя определить пароль/учетную запись по умолчанию AP/контроллера.<br><br>2. Попытаться войти в интерфейс управления AP (HTTPS/SSH/консоль контроллера) с паролем по умолчанию.<br><br>3. Попытаться подключить клиента к SSID с PSK/паролем, заданным производителем. | 1. Успех: Штатный пароль по умолчанию в конфигурации не используется.<br><br>2. Успех: Вход с паролем по умолчанию отклонен; событие зафиксировано в журнале контроллера/hostapd.<br><br>3. Успех: Подключение с паролем по умолчанию невозможно. |
| Меры реализуются за счет средств идентификации и аутентификации, примененных в точках беспроводного доступа, ином оборудовании беспроводной сети, устройствах пользователей. | Проверить, что 802.1X/WPA-EAP включены на AP/контроллере и на клиенте (`wpa_supplicant.conf`: `key_mgmt=WPA-EAP`), а не только на одном из звеньев. | Успех: Идентификация и аутентификация выполняются средствами AP/контроллера и клиента. |
| Субъект: Пользователи и устройства беспроводного доступа.<br><br>Условия: У Системы К1.<br><br>Должно обеспечиваться сокрытие имени сети (SSID) в списке доступных сетей. | 1. На AP/контроллере включить скрытие SSID (`ignore_broadcast_ssid=1` в hostapd либо эквивалент контроллера).<br><br>2. На тестовом клиенте выполнить сканирование: `iw dev wlan0 scan` / `nmcli dev wifi list` без заранее известного имени сети. | 1. Успех: Широковещательная трансляция SSID отключена.<br><br>2. Успех: Имя сети не отображается в списке доступных сетей; подключение возможно только по документированной процедуре с известным SSID. |
| Автопроверка Linux-хоста | `./check_all.sh --measure ЗБД.1 --class K3`<br><br>`./check_all.sh --measure ЗБД.1 --class K1 --with-enhancements` | Зафиксированы вердикты PASS/FAIL/SKIP/NA по локальным признакам (hostapd/NetworkManager, WPA2/WPA3/802.1X, отсутствие пароля по умолчанию). При отсутствии беспроводного стека — NA. SKIP не считается провалом испытания СПО. |

Требования к усилению:

1) должно обеспечиваться сокрытие имени сети (SSID) в списке доступных сетей;
2) для управления учетными записями и учетными данными субъектов беспроводного доступа в беспроводной локальной вычислительной сети должны использоваться системы (средства) управления учетными записями;
3) символьное название беспроводной точки доступа, служащее для идентификации ее пользователями и устройствами пользователей, точкой доступа не должно транслироваться широковещательно и, соответственно, не должно отражаться в списке видимых точек доступа на устройствах пользователей и иных субъектов доступа;
4) аутентификация устройств при подключении к точкам беспроводного доступа в информационной системе обеспечивается с использованием протоколов аутентификации.
