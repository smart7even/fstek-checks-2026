# 19.1. АВЗ.1 Антивирусная защита устройств

**Скрипт:** `fstek_audit/checks/AVZ/AVZ_01.sh`

Цель: Обеспечение антивирусной защиты информационной системы на устройствах, включающее обнаружение вредоносного программного обеспечения и реагирование на его обнаружение.

Регламентирование: В эксплуатационной документации на информационную систему должны быть определены:

- порядок учета устройств, на которых необходимо применение средств антивирусной защиты;
- порядок и правила проведения периодических проверок устройств и серверов на наличие компьютерных вирусов;
- действия по реагированию на обнаружение в информационной системе объектов, подвергшихся заражению вредоносным программным обеспечением;
- порядок и правила обновления баз данных признаков вредоносных компьютерных программ (вирусов).

Описание реализации, действий и результатов при испытаниях:

| Требование | Действие | Результат |
|------------|----------|-----------|
| Должны быть определены физические и виртуальные устройства, входящие в состав информационной системы, на которых необходимо применение средств антивирусной защиты. | Сопоставить перечень устройств/серверов в ОРД с фактически установленными агентами (`systemctl status clamd kesl drwebd`, `kesl-control -S`, `drweb-ctl`). | Успех: Для каждого устройства из перечня средство антивирусной защиты установлено; устройства вне перечня, где АВЗ не требуется, зафиксированы как не подлежащие установке. |
| Должны выполняться установка, конфигурирование и управление средствами антивирусной защиты. Средствам антивирусной защиты должны быть предоставлены права доступа к объектам, подлежащим проверке. | 1. Проверить, что служба AV активна и конфигурация загружена (`clamconf`, `kesl-control --get-settings`, `drweb-ctl cfshow`).<br><br>2. Убедиться, что агент имеет доступ к проверяемым каталогам (включая точки монтирования съемных носителей). | 1. Успех: Средство установлено, сконфигурировано и управляется.<br><br>2. Успех: Объекты, подлежащие проверке, доступны средству антивирусной защиты. |
| Средства антивирусной защиты должны быть настроены на проведение периодических проверок устройств на наличие вредоносного программного обеспечения. | Проверить systemd-таймер/cron задания сканирования (`systemctl list-timers`, `/etc/cron.d`, задания `clamscan`/`kesl-control`/`drweb-ctl`) и запустить внеочередную проверку по команде. | Успех: Периодическая проверка настроена и выполняется; журнал содержит результат сканирования. |
| На устройствах, через которые может быть внедрено вредоносное ПО, должна быть настроена проверка в масштабе времени, близком к реальному, объектов (файлов) из внешних источников (съемные носители, сетевые подключения, в том числе к сетям общего пользования, и другие внешние источники). | 1. Включить on-access (`clamonacc`, модуль реального времени KESL/Dr.Web).<br><br>2. Скопировать тестовый объект EICAR с USB и по SMB/HTTP на АРМ. | 1. Успех: Режим проверки, близкий к реальному времени, включен для внешних источников.<br><br>2. Успех: Объект обнаружен до завершения сохранения/открытия; доступ заблокирован. |
| Должны обеспечиваться выявление вредоносного ПО и реагирование на его обнаружение на устройствах и серверах при подключении съемных носителей, а также периодически или по команде в процессе функционирования, в соответствии с эксплуатационной документацией. | 1. Подключить съемный носитель с EICAR.<br><br>2. Запустить проверку по команде средства антивирусной защиты. | 1. Успех: Объект обнаружен при подключении носителя; выполнено действие по регламенту (удаление, карантин, блокирование).<br><br>2. Успех: Проверка по команде обнаруживает объект и выполняет то же реагирование. |
| Должны быть определены и выполняться действия по реагированию на обнаружение объектов, подвергшихся заражению. | По журналу AV и ОРД выполнить цепочку реагирования: карантин/удаление, уведомление администратора безопасности, фиксация инцидента. | Успех: Действия реагирования выполнены в соответствии с эксплуатационной документацией; зараженный объект недоступен для запуска. |
| Должно выполняться обновление баз данных признаков вредоносных компьютерных программ в соответствии с информацией разработчика средства, в порядке, установленном в эксплуатационной документации. | Проверить службу обновления (`freshclam`, `kesl-control --update`, `drweb-ctl update`) и дату баз; при необходимости запустить обновление. | Успех: Базы обновлены в установленном порядке; источник — разработчик средства или утвержденный локальный ресурс. |
| После обновления баз должна выполняться проверка устройств на наличие вредоносного программного обеспечения. | Сразу после обновления баз запустить сканирование устройства/сервера штатным заданием или командой. | Успех: Проверка после обновления баз выполнена; результат зарегистрирован. |
| Автопроверка Linux-хоста | `./check_all.sh --measure АВЗ.1 --class K3` | Зафиксированы вердикты PASS/FAIL/SKIP по локальным признакам (установленный AV, обновление баз, расписание сканирования, on-access). Перечень устройств, порядок реагирования и проверка после обновления баз, не подтвержденные локально, дают SKIP. SKIP не считается провалом испытания СПО. |

Требования к усилению:

1) в информационной системе должно обеспечиваться выявление вредоносного программного обеспечения и реагирование на его обнаружение на устройствах средством антивирусной защиты до загрузки операционных систем;
2) в информационной системе должно обеспечиваться централизованное управление антивирусной защитой за счет применения средств, обеспечивающих централизованное управление средствами антивирусной защиты;
3) в информационной системе должна обеспечиваться настройка средств антивирусной защиты на устройствах информационной системы, через которые в нее может быть внедрено вредоносное программное обеспечение, обеспечивающая проверку в масштабе времени, близком к реальному, объектов (файлов) из внешних источников при загрузке, открытии или исполнении таких файлов.
