**Цель**: Обеспечение защиты пользовательских данных, передаваемых, обрабатываемых и хранящихся в веб-приложении СПО.

**Регламентирование**: В эксплуатационной документации для СПО должны быть определены:

- объекты доступа, содержащиеся в веб-приложении СПО;
- перечень типов пользователей веб-приложения.

Описание реализации, действий и результатов при испытаниях:

| Требование | Действие | Результат |
|------------|----------|-----------|
| **Субъект: Все типы пользователей.**<br><br>Сетевое взаимодействие субъектов и объектов доступа идет через программный интерфейс, защита данных в котором обеспечивается по ЗПИ.1. | Открыть https://example.ru/admin и https://example.ru/public; выполнить чтение и изменение пользовательских данных; вызвать API по HTTP и HTTPS. | Успех: Операции выполняются только через документированный интерфейс СПО; HTTP отсутствует либо перенаправляется на HTTPS. |

**Параметры безопасности в интерфейсе администратора безопасности (СПБ.5):**

Все перечисленные параметры должны быть доступны для оперативного редактирования из интерфейса СПО (`example.ru/admin`) администратору безопасности, с ограничениями, исключающими ослабление политик безопасности ниже значений, установленных методикой и требованиями к СПО (мера СПБ.5).

- перечень объектов пользовательских данных;
- директивы запрета кэширования чувствительных данных в браузере;
- признак отключения autocomplete для полей аутентификации и ПДн;
- заголовки защиты от межсайтового скриптинга.

Требования к усилению:

1) исключено кэширование пользовательских данных, определяемых оператором, в веб-браузере;
2) отключено автоматическое заполнение форм для полей пользовательских данных, определяемых оператором;
3) обеспечена защита от компрометации посредством межсайтового скриптинга заголовками безопасности;
4) обеспечена защита от подмены (перекрытия) элементов графического интерфейса.
