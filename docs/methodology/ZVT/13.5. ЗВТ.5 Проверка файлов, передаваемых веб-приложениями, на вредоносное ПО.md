# 13.5. ЗВТ.5 Проверка файлов, передаваемых веб-приложениями, на вредоносное ПО

**Скрипт:** `fstek_audit/checks/ZVT/ZVT_05.sh`

Цель: Обеспечение антивирусной защиты веб-приложений информационной системы, включающее обнаружение вредоносного программного обеспечения и реагирование на его обнаружение.

Регламентирование: Не предъявляются.

Описание реализации, действий и результатов при испытаниях:

| Требование | Действие | Результат |
|------------|----------|-----------|
| Должна обеспечиваться проверка всех файлов, передаваемых веб-приложениями, на вредоносное программное обеспечение в соответствии с мерой защиты информации АВЗ.1. | 1. Войти в СПО на example.ru/admin и загрузить через форму передачи файлов тестовый файл-индикатор вредоносного программного обеспечения (EICAR).<br><br>2. Повторить загрузку с example.ru/public, если внешняя передача файлов предусмотрена.<br><br>3. Загрузить допустимый файл разрешенного типа. | 1. Успех: Файл не сохранен либо помещен в карантин; средство антивирусной защиты зафиксировало обнаружение и выполнило реагирование.<br><br>2. Успех: Файл отклонен аналогично; если внешняя загрузка не предусмотрена, проверка к этому интерфейсу не применяется.<br><br>3. Успех: Допустимый файл принят после проверки. |
| Проверка должна включать анализ всех передаваемых в теле запроса файлов, а также составляющих тело запроса скриптов и данных, поступающих в веб-приложение. | 1. Передать на example.ru/admin файл во вложении тела запроса (multipart).<br><br>2. Передать в теле запроса скрипт и данные, не оформленные как отдельный файл.<br><br>3. Передать несколько файлов в одном запросе, один из которых содержит признак вредоносного программного обеспечения. | 1. Успех: Вложение в теле запроса проверено.<br><br>2. Успех: Скрипт и данные в теле запроса проанализированы; вредоносное содержимое отклонено.<br><br>3. Успех: Проверены все файлы запроса; зараженный файл не принят. |
| Должен быть исключен автоматический запуск переданных файлов в операционной системе на стороне веб-приложения или пользователя (например, путем осуществления фильтрации исполняемых файлов, определения соответствия типа файла его содержимому, предотвращения маскирования исполняемых файлов под иные форматы). | 1. Загрузить на example.ru/admin исполняемый файл.<br><br>2. Загрузить исполняемый файл, маскированный под иной формат (расширение и объявленный тип не соответствуют содержимому).<br><br>3. После загрузки допустимого файла проверить, что на стороне веб-приложения и в браузере пользователя автоматический запуск не выполнен. | 1. Успех: Исполняемый файл отфильтрован, не запущен.<br><br>2. Успех: Несоответствие типа содержимому обнаружено; файл отклонен.<br><br>3. Успех: Автоматический запуск переданного файла отсутствует. |
| Автопроверка Linux-хоста | `./check_all.sh --measure ЗВТ.5 --class K3` | Зафиксированы вердикты PASS/FAIL/SKIP/NA по локальным признакам (установленное средство антивирусной защиты, обновления баз, интеграция веб/прокси с антивирусной проверкой). SKIP не считается провалом испытания СПО. |
