**Цель**: Доступ внутренних непривилегированных пользователей реализован исключительно через двухфакторную аутентификацию.

**Регламентирование**: Не предъявляются.

Описание реализации, действий и результатов при испытаниях:

| Требование | Действие | Результат |
|------------|----------|-----------|
| **Субъект: Внутренний непривилегированный.**<br><br>Вход на example.ru/admin только по паролю не допускается. | Войти на example.ru/admin только по паролю. | Успех: Доступ не предоставлен. |
| Вход с вторым фактором (ЕСИА либо иная информационная система) допускается. | Войти на example.ru/admin с вторым фактором. | Успех: Вход осуществлен. |
| **Субъект: Тот же пользователь с example.ru/public.**<br><br>Публичный контур не обходит второй фактор внутренней УЗ. | Войти той же внутренней УЗ на example.ru/public только по паролю. | Успех: Вход внутренней УЗ в public-контур без второго фактора не принят либо внутренняя УЗ там не используется. |

**Параметры безопасности в интерфейсе администратора безопасности (СПБ.5):**

Все перечисленные параметры должны быть доступны для оперативного редактирования из интерфейса СПО (`example.ru/admin`) администратору безопасности, с ограничениями, исключающими ослабление политик безопасности ниже значений, установленных методикой и требованиями к СПО (мера СПБ.5).

- признак обязательного второго фактора для внутренних непривилегированных пользователей;
- допустимые поставщики второго фактора.
