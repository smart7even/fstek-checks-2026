# 19.3. АВЗ.3 Антивирусная проверка сетевого трафика

**Скрипт:** `fstek_audit/checks/AVZ/AVZ_03.sh`

Цель: Обеспечение антивирусной защиты сетевого трафика, включающее обнаружение вредоносного программного обеспечения и реагирование на его обнаружение.

Регламентирование: В эксплуатационной документации на информационную систему должен быть определен:

- порядок осуществления антивирусной защиты сетевого трафика.

Описание реализации, действий и результатов при испытаниях:

| Требование | Действие | Результат |
|------------|----------|-----------|
| Должна выполняться антивирусная проверка файлов, извлекаемых из сетевого трафика. | На периметрном прокси/NGFW/ICAP (`squid`+`c-icap`+ClamAV, HAVP, антивирусный модуль МЭ) подтвердить, что файлы из HTTP/HTTPS/FTP извлекаются и передаются на AV, а не только что на хосте установлен пакет антивируса. | Успех: Настроена проверка извлекаемых из трафика файлов конкретным средством антивирусной защиты или многофункциональным МЭ. |
| Должен выполняться анализ файлов, извлекаемых из сетевого трафика, на предмет наличия вредоносного программного обеспечения в масштабе времени, близком к реальному. | С АРМ внутренней сети загрузить тестовый объект EICAR по HTTP через проверяемый канал (прокси/NGFW). | Успех: Загрузка заблокирована в ходе передачи; объект не сохранен на АРМ как доступный файл. |
| Анализ должен выполняться с использованием сигнатурного метода обнаружения, хэш-сумм и других индикаторов. | 1. В конфигурации AV/ICAP убедиться, что включены сигнатурные базы и проверка хэш-сумм/индикаторов.<br><br>2. Повторить загрузку объекта с известной сигнатурой и объекта с известным вредоносным хэшем. | 1. Успех: Сигнатурный метод и индикаторы (хэш и иные) применяются к извлекаемым файлам.<br><br>2. Успех: Оба объекта обнаружены. |
| По результатам антивирусной проверки должно выполняться реагирование в соответствии с порядком, установленным в эксплуатационной документации. | По журналу прокси/NGFW/ICAP зафиксировать действие (block/drop/quarantine), адреса источника и назначения и уведомление, предусмотренное ОРД. | Успех: Реагирование выполнено по установленному порядку; вредоносный файл до получателя не доставлен. |
| Автопроверка Linux-хоста | `./check_all.sh --measure АВЗ.3 --class K3` | Зафиксированы вердикты PASS/FAIL/SKIP по локальным признакам ICAP/прокси/NGFW с антивирусной проверкой трафика. Наличие пакета AV без извлечения и проверки файлов из сетевого трафика не считается основанием для PASS. SKIP не считается провалом испытания СПО. |

Требования к усилению:

1) в информационной системе должен обеспечиваться анализ файлов, извлекаемых из сетевого трафика, на предмет наличия вредоносного программного обеспечения с использованием эвристических методов обнаружения;
2) в информационной системе должен обеспечиваться анализ файлов, извлекаемых из сетевого трафика, на предмет наличия вредоносного программного обеспечения на прикладном уровне для установленных в эксплуатационной документации приложений (веб-приложений, клиентов файловых хранилищ, мессенджеров и иных приложений);
3) в информационной системе должен осуществляться анализ извлекаемых из сетевых пакетов данных, инкапсулированных в преобразованном (кодированном) виде, на предмет наличия вредоносного программного обеспечения.
